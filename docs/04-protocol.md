# 04 - 隧道协议

日期：2026-10-03

服务端和客户端必须讲同一种语言。本协议极简，共两种帧。

## 传输层

TCP 长连接。默认端口 `51820`（借用 WireGuard 的端口号，好记）。

## 帧格式

所有数据都是**定长帧头 + 变长载荷**：

```
+--------+--------+------------------+
| LEN(2) | TYPE(1)| PAYLOAD (LEN)    |
+--------+--------+------------------+
```

- `LEN`：大端 uint16，PAYLOAD 字节数（不含帧头）
- `TYPE`：帧类型
- `PAYLOAD`：载荷

## 帧类型

| TYPE | 名称 | 方向 | PAYLOAD |
|------|------|------|---------|
| `0x01` | HELLO | C→S | `password` (utf-8) |
| `0x02` | WELCOME | S→C | `vpn_ip` (utf-8, 如 "10.8.0.2")，认证失败则断开 |
| `0x03` | DATA | 双向 | 完整 IP 包（含 IP 头） |
| `0x04` | PING | C→S | 空（保活用，可选） |
| `0x05` | PONG | S→C | 空 |

## 建连流程

```
Client                          Server
  |---- HELLO(password) ----------->|
  |<--- WELCOME("10.8.0.2") --------|
  |==== DATA(IP包) 双向传输 ========>|
```

1. 客户端 TCP 连接服务端。
2. 发送 HELLO，载荷为口令。
3. 服务端校验口令：
   - 通过 → 分配 VPN IP（如 `10.8.0.2`），回 WELCOME；
   - 失败 → 直接断开 TCP。
4. 之后双方互发 DATA 帧，载荷为原始 IP 包。
5. 客户端每 30 秒发 PING 保活（NAT 超时用）。

## IP 分配

- 服务端 TUN 网卡：`10.8.0.1/24`
- 客户端按连接顺序分配：`10.8.0.2`、`10.8.0.3`…
- 服务端维护 `vpn_ip → socket` 映射表，用于下行选路。

## 为什么这样设计

- 定长帧头：TCP 是流式协议，必须自己分包。2 字节长度足够（IP 包最大 65535）。
- 先认证后传输：HELLO 是第一帧，未认证不分配资源，防扫段。
- 明文口令：v1 演示用，加 TLS 后自然解决（见架构文档安全说明）。
