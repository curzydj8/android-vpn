# 错误 001：测试客户端源 IP 与服务端分配不一致

日期：2026-10-03
阶段：服务端联调测试

## 现象

Python 测试客户端握手成功（分配到 `10.8.0.3`），发送 ICMP Echo Request（源 IP 硬编码为 `10.8.0.2`）到服务端 `10.8.0.1`，5 秒超时未收到回包。

## 根因

1. 之前的握手测试已占用 `10.8.0.2`，本次测试实际分配到的是 `10.8.0.3`。
2. 测试代码硬编码源 IP 为 `10.8.0.2`，构造的 IP 包源地址与分配不符。
3. 服务端内核收到包后，回包目标是 `10.8.0.2`。
4. 服务端 `clients` 映射表里只有 `10.8.0.3 → socket`，查不到 `10.8.0.2`，回包被丢弃。

**本质**：客户端必须使用服务端分配的 VPN IP 作为 TUN 包的源地址，否则下行选路失败。

## 修复

测试代码改为从 WELCOME 帧解析实际分配的 IP，再用该 IP 构造数据包：

```python
ft, payload = recv_frame(s)
my_ip = payload.decode()  # 用分配的，不用硬编码的
src = socket.inet_aton(my_ip)
```

## 验证

修复后 ping 往返成功：`10.8.0.4 → 10.8.0.1`，收到 ICMP Echo Reply (type=0)。

## 教训

- VPN 客户端的 TUN 地址必须由服务端统一分配，客户端不可自定。
- 安卓端实现时：从 WELCOME 拿到 IP 后，再配置 VpnService.Builder.setAddress()。
