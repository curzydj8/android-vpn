# 01 - 架构设计

日期：2026-10-03

## 目标

做一个**真正能用的**安卓 VPN 应用：手机上打开 App、点连接，手机流量走加密隧道经自建服务端出公网。

## 为什么不用 WireGuard/OpenVPN？

| 方案 | 优点 | 缺点 |
|------|------|------|
| WireGuard 官方库 | 成熟、安全 | 需 NDK 编译 Go 库，构建复杂，不利于"记录全过程" |
| OpenVPN (ics-openvpn) | 成熟 | 引入第三方大库，核心逻辑被隐藏 |
| **自研轻量隧道** | 全程可见、可讲清楚每一行、构建简单 | 安全性不如成熟方案（演示用） |

本项目选**自研轻量隧道**：把 VPN 的每一层都摊开，便于学习和记录。生产环境请用 WireGuard。

## 整体架构

```
┌─────────────────────────────────┐
│           Android 手机           │
│  ┌──────────┐    ┌────────────┐  │
│  │ App UI   │───►│ VpnService │  │
│  │(连接按钮) │    │ (TUN网卡)  │  │
│  └──────────┘    └─────┬──────┘  │
└────────────────────────┼────────┘
                         │ TCP 隧道
                         │ (自定义协议)
┌────────────────────────┼────────┐
│         VPS 服务端       │        │
│  ┌─────────────┐ ┌─────▼──────┐ │
│  │ vpn_server  │ │ TUN 网卡   │ │
│  │ (Python)    │ │ (tun0)     │ │
│  └─────────────┘ └─────┬──────┘ │
└────────────────────────┼────────┘
                         │ iptables NAT
                         ▼
                      Internet
```

## 数据流向

**上行（手机 → 公网）：**
1. App 的流量被 VpnService 的 TUN 接口拦截（IP 包）
2. 客户端按协议封装成帧，经 TCP 发往服务端
3. 服务端拆帧，写入服务端 TUN (`tun0`)
4. Linux 内核路由 + iptables MASQUERADE 做 NAT，包出公网

**下行（公网 → 手机）：**
1. 回包到达服务端 `tun0`
2. 服务端读出 IP 包，按客户端 VPN IP 找到对应 TCP 连接
3. 封装成帧发回客户端
4. 客户端写入手机 TUN，内核投递给 App

## 模块划分

| 模块 | 位置 | 职责 |
|------|------|------|
| `server/vpn_server.py` | VPS | TCP 监听、握手认证、TUN 读写、包转发、NAT |
| `server/setup.sh` | VPS | 一键配置：建 TUN、开转发、iptables 规则 |
| `android/` | 手机 | VpnService、隧道读写线程、UI |

## 安全说明（诚实）

- v1 用口令认证 + 裸 TCP（局域网/测试用）。
- 公网部署前必须加 TLS（`docs/06-tls.md` 预留）。
- 不要用本项目传输敏感数据，直到加上 TLS。
